# Need for Speed: Most Wanted (2012) 3DS - Full World Streaming Progress

## 1. Project Goal
Bring the **entire open world of Fairhaven City** from the retail PC game (*Need for Speed: Most Wanted 2012*, Criterion Chameleon engine) to the Nintendo 3DS with **dynamic spatial chunk streaming (loading/unloading)**, maintaining 60 FPS within the 3DS Linear Heap memory budget.

## 3. Streaming Architecture & Implementation

### 3.1 Spatial Partitioning
- **Grid Cell Size**: $500\text{m} \times 500\text{m}$ spatial sectors in mesh-local coordinates.
- **Total World Geometry**:
  - **96 Active Sectors** generated by `tools/extract_world_sectors.py` from all 184 bundles (8 ARENAs + 7 DISTRICTs + 169 TRK_UNITs).
  - **1,614,879 Vertices** (20 bytes each: float3 position + uint8x4 lighting tint + uint16x2 atlas UV).
  - **2,255,437 Triangles** (indexed 16-bit uint16).
  - **43.7 MB Total Mesh Data** across all 96 sector files stored in `romfs:/assets/sectors/sec_<gx>_<gz>.mwmesh`.
  - Master binary manifest stored at `romfs:/assets/world_manifest.bin` ($7.3\text{ KB}$, 96 sector records).
  - LOD deduplication dropped 543 duplicate/lower-detail renderables from the 1,197 candidates scanned.

### 3.2 Dynamic Runtime Streaming (`src/renderer/world_mesh.cpp`)
- **Initialization**:
  - Reads `romfs:/assets/world_manifest.bin` at startup into `g_manifest_sectors`.
  - Gracefully falls back to monolithic `fairhaven_block.mwmesh` if manifest is absent.
  - Automatically loads the spawn sector and immediate neighbours on the harbour apron at boot.
- **Spatial Hysteresis & Streaming Thresholds**:
  - **Load Distance ($R_{load}$)**: $650.0\text{m}$ distance from car to sector AABB.
  - **Unload Distance ($R_{unload}$)**: $900.0\text{m}$ (250m hysteresis band prevents thrashing at sector seams).
- **Hitch Prevention**:
  - Frame-budgeted loading: at most 1 sector is loaded per frame to eliminate frame rate drops while driving at $300\text{ km/h}$.
  - Sorts candidate sectors by proximity, loading the nearest sector first.
- **Linear Memory Safety (GPU Heap Budget)**:
  - Guard: Checks `linearSpaceFree() >= 2.0 MB` before every allocation.
  - If linear memory runs low, proactively evicts the furthest sector from the car, ensuring `linearAlloc` never fails.
  - At any given time, only $\sim 3 - 6$ sectors ($\approx 4 - 8\text{ MB}$ VRAM) are resident in memory.

### 3.3 Dynamic Multi-Sector Ground Collision
- **Local Ground Grids**:
  - Each loaded $500\text{m}$ sector generates its own local $126 \times 126$ cell ($4\text{m}$ resolution) height table ($\approx 31\text{ KB}$ CPU heap).
  - Evaluates up-facing drivable surfaces ($|n_y| / len \ge 0.40$).
  - Tracks both `ground_lo` and `ground_hi` for stacked bridges/decks.
- **Instant $O(1)$ Ground Height Sampling**:
  - `world_mesh_ground_height(x, z, fallback)` maps `(x, z)` directly to the matching loaded sector and local cell.
  - Seamless fallback interpolation across sector seams.

  - Created `tools/extract_world_sectors.py`.

  - Extracted **96 spatial sectors** covering the entire Fairhaven open world.

- [x] **Milestone 3: Dynamic World Streaming Runtime Engine**
  - Rewrote `src/renderer/world_mesh.cpp` into a full dynamic streaming engine.
  - Added spatial AABB distance calculations, $650\text{m}$ load, $900\text{m}$ unload hysteresis.
  - Implemented linear heap memory guard and 1-sector-per-frame streaming budget.
- [x] **Milestone 4: Seamless Ground Collision Across Sectors**
  - Implemented per-sector local height grids ($126 \times 126$ cells, $4\text{m}$ resolution).
  - Added seamless multi-sector ground height sampling and edge seam resolution.
