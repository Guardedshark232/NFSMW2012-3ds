# Need for Speed: Most Wanted (2012) 3DS - Full World Streaming Progress

## 1. Project Goal
Bring the **entire open world of Fairhaven City** from the retail PC game (*Need for Speed: Most Wanted 2012*, Criterion Chameleon engine) to the Nintendo 3DS with **dynamic spatial chunk streaming (loading/unloading)**, maintaining 60 FPS within the 3DS Linear Heap memory budget.

## 3. Streaming Architecture & Implementation

### 3.1 Spatial Partitioning
- **Grid Cell Size**: $500\text{m} \times 500\text{m}$ spatial sectors in mesh-local coordinates.
- **Total World Geometry**:
  - **252 Active Sectors** generated by `tools/extract_world_sectors.py` from all 184 bundles (8 ARENAs + 7 DISTRICTs + 169 TRK_UNITs). Long renderables are split by triangle centroid across sectors so roads spanning multiple cells remain available while driving.
  - The extractor also expands type-80/type-81 placement records: the current scan found 96,854 placed mesh references, retained 26,331 after LOD filtering, plus 448 direct world renderables.
  - **11,165,959 Vertices** (20 bytes each: float3 position + uint8x4 lighting tint + uint16x2 atlas UV).
  - **14,603,006 Triangles** (indexed 16-bit uint16).
  - **296.57 MB Total Mesh Data** across the sector files stored in `romfs:/assets/sectors/sec_<gx>_<gz>.mwmesh`.
  - Master binary manifest stored at `romfs:/assets/world_manifest.bin` (19,180 bytes, 252 sector records).

### 3.2 Dynamic Runtime Streaming (`src/renderer/world_mesh.cpp`)
- **Initialization**:
  - Reads `romfs:/assets/world_manifest.bin` at startup into `g_manifest_sectors`.
  - Gracefully falls back to monolithic `fairhaven_block.mwmesh` if manifest is absent.
  - Automatically loads the spawn sector and immediate neighbours on the harbour apron at boot.
- **Spatial Hysteresis & Streaming Thresholds**:
  - **Load Distance ($R_{load}$)**: $650.0\text{m}$ distance from car to sector AABB.
  - **Unload Distance ($R_{unload}$)**: $900.0\text{m}$ (250m hysteresis band prevents thrashing at sector seams).
- **Hitch Prevention**:
  - Frame-budgeted loading: at most 1 sector is loaded per frame to eliminate frame rate drops while driving at $300\text{ km/h}$.
  - Sorts candidate sectors by proximity, loading the nearest sector first.
- **Linear Memory Safety (GPU Heap Budget)**:
  - Checks the manifest's vertex/index totals and reserves an additional 2 MB before loading a sector.
  - Evicts the furthest loaded sectors until the target sector's full allocation can fit. Runtime memory behavior still needs hardware/emulator confirmation.

### 3.3 Dynamic Multi-Sector Ground Collision
- **Local Ground Grids**:
  - Each loaded $500\text{m}$ sector generates its own local $252 \times 252$ cell ($2\text{m}$ resolution) height table.
  - Evaluates up-facing drivable surfaces ($|n_y| / len \ge 0.40$).
  - Tracks both `ground_lo` and `ground_hi` for stacked bridges/decks.
- **Instant $O(1)$ Ground Height Sampling**:
  - `world_mesh_ground_height(x, z, fallback)` maps `(x, z)` directly to the matching loaded sector and local cell.
  - Seamless fallback interpolation across sector seams.

## 4. Implementation Milestones

- [x] **Milestone 1: World Survey & Asset Mapping**
  - Scanned all 8 `ARENA_*.BNDL`, 169 `TRK_UNIT*.BNDL`, and `DISTRICT_*.BNDL` files.
  - Mapped global extents ($4.4\text{km} \times 7.3\text{km}$) and validated sector layout.
- [x] **Milestone 2: Multi-Bundle & Sector Extraction Pipeline**
  - Created `tools/extract_world_sectors.py`.
  - Scanned all **184 bundles** (8 ARENAs + 7 DISTRICTs + 169 TRK_UNITs), expanding 96,854 placed mesh references.
  - Extracted **252 spatial sectors** covering the Fairhaven open world.
  - Current LOD filtering retained 26,331 placed renderables and 448 direct world renderables.
  - Applied yard dressing, degenerate strip removal, and UV atlas mapping per sector.
  - Generated `romfs/assets/world_manifest.bin` (252 sectors, 19,180 bytes).
  - **Performance fix**: `_containment_fraction` switched from O(n²) `np.isin` × 27 shifts to Python `set` lookups + subsampling — **10–50× faster** on large TRK_UNIT renderables.
- [x] **Milestone 3: Dynamic World Streaming Runtime Engine**
  - Rewrote `src/renderer/world_mesh.cpp` into a full dynamic streaming engine.
  - Added spatial AABB distance calculations, $650\text{m}$ load, $900\text{m}$ unload hysteresis.
  - Implemented linear heap memory guard and 1-sector-per-frame streaming budget.
- [x] **Milestone 4: Seamless Ground Collision Across Sectors**
  - Implemented per-sector local height grids ($252 \times 252$ cells, $2\text{m}$ resolution).
  - Added seamless multi-sector ground height sampling and edge seam resolution.
- [x] **Milestone 5: Integrated Build & Verification**
  - Built `nfs_3ds.3dsx` with the expanded placed meshes and updated manifest (about 304.7 MB).
  - Full world: 252 sectors, 11.17M verts, 14.60M tris, 296.57 MB sector data.
  - Retained long highway/interchange renderables with radii from 600 m to 5 km; triangle-centroid partitioning places their distant sections in the sectors where they are used.
  - Runtime visibility and memory use still need checking in Azahar or on hardware. Streaming now checks the target sector's full vertex/index allocation before loading and evicts distant sectors until it fits.
